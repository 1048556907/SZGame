# Design

## Context

项目目前无 README.md，功能已覆盖游戏盒子核心、分组管理、自动更新、设置、封面管理等。`doc/` 目录下有 4 张界面截图可直接引用（首页、详情抽屉、收藏夹/分组管理、设置页）。

技术栈已确定：Electron 32 + React 18 + TypeScript + Vite + sql.js。NSIS 安装包构建通过 `electron-builder` 完成。详见 [proposal.md](./proposal.md)。

## Goals / Non-Goals

**Goals:**
- 编写一份结构清晰的中文 README.md，帮助新用户在 30 秒内理解 SZGame 是什么、有什么用
- 嵌入 `doc/` 下的 4 张截图，直观展示主要界面
- 提供开发和构建命令，方便开发者快速上手

**Non-Goals:**
- 不做 API 级别的接口文档（当前不需要对外暴露 API）
- 不写贡献者指南（暂无开源贡献规划）
- 不更新截图（直接使用 doc/ 目录现有文件）
- 不新增或修改任何源代码

## Decisions

### Decision: 截图引用路径
**选择**：在 README 中使用相对路径 `doc/01首页.png` 等引用本地截图

**理由**：图片已在仓库内，相对路径在 GitHub / Gitee 等平台可直接渲染。不拷贝图片、不重命名，避免产生冗余文件。

**备选方案**：
- 将图片移动到 `images/` 或新建 `assets/readme/` 目录 —— 放弃，doc/ 命名语义清晰（"文档"）
- 使用外链图片 —— 放弃，依赖外部网络和平台

### Decision: README 语言
**选择**：全中文

**理由**：目标用户为中文社区玩家和开发者；截图 UI 也是中文；项目暂未国际化。

**备选方案**：中英双语 —— 放弃，维护成本翻倍且当前无国际用户需求。

### Decision: 章节结构
**选择**：按"简介 → 功能特性 → 界面预览 → 快速开始 → 构建 → 技术栈 → 目录结构 → License"顺序

**理由**：遵循 GitHub 上 Electron 项目 README 常见组织方式，用户扫描顺序自然：先知道是什么 → 再看好不好 → 再跑起来 → 再深入。

## Risks / Trade-offs

| 风险 | 缓解措施 |
|---|---|
| 截图文件名包含中文，部分 Markdown 渲染器可能编码问题 | 在 README 中用 URL 编码（`doc/01%E9%A6%96%E9%A1%B5.png`）引用，同时保留中文文件名 |
| 文档与实际代码/命令不同步 | 在 README 中明确标注"文档版本对应 v1.0.3"，后续变更时同步更新 |
| 截图分辨率过高导致渲染慢 | 当前 4 张均为 PNG 截图，尺寸合理，无需额外处理 |
